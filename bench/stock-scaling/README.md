# Stock compiler scaling measurements

**Status: measurement artifacts, not a compiler optimization or qualification.**

Unchanged upstream Bend 2.0.36 (`ae1101ca7d15364f9274fa6b1367d175884a7da7`) and current upstream main reporting 2.0.39 (`ea66e0044fc1632c28e35b7b0f0d2263d77e3449`) were measured under Bun 1.3.10. No compiler file is changed on this branch. [versions.json](versions.json) records every measured compiler-source file hash.

[report.md](report.md) has phase wall/peak-RSS tables, growth fits, failure classification, overhead controls and limitations. [results.json](results.json) contains individual numeric records, phase medians, source byte counts, output checksums, cap readbacks and fits. The public inputs are generated by [generate.py](generate.py); [phase.ts](phase.ts) observes unchanged compiler APIs. Application inputs were measured privately and are excluded from this repository, along with their paths and diagnostics.

The two synthetic definition-count families show approximately linear growth over 2,000–32,000 definitions. Some heterogeneous real-prefix slopes exceed one, but those do not isolate a compiler asymptotic bug. Large real-prefix results are censored by memory limits or compatibility failures. These findings say nothing about the separate paged/module-mode experiments.

## Reproduce

Use a disposable **normal-size Boat VM**, Linux cgroup v2 with a user systemd session and Bun 1.3.10. Do not run the series on the machine hosting your work. The driver refuses unlimited memory or nonzero swap, enforces a 120 s command timeout, disables core dumps and limits output file size. Run one compiler at a time. An OOM may terminate the scope before its final receipt is written; retain the systemd `Result` and `MemoryPeak` instead of treating that run as successful.

From this checkout, prepare separate unchanged upstream worktrees:

```sh
git worktree add --detach ../stock-2.0.36 ae1101ca7d15364f9274fa6b1367d175884a7da7
git worktree add --detach ../stock-2.0.39 ea66e0044fc1632c28e35b7b0f0d2263d77e3449
```

For one measured input (replace the stock path for the other version):

```sh
systemd-run --user --scope -q \
  -p MemoryMax=3700000000 -p MemorySwapMax=0 -- \
  python3 bench/stock-scaling/measure.py ../stock-2.0.39 \
  independent 32000 scratch-observed
```

Run `independent` and `fanin` at 2000, 4000, 8000, 16000 and 32000, with three fresh-process repetitions each. The original series randomized the cases within each repetition with Python `random.Random(2038 + rep).shuffle`, with both versions on the same VM. Each output directory must be new. A bounded wrapper like the one above must be used for **every** run. The original series also capped its controller separately at 512 MiB; combined compiler/controller budgets stay below 4 GiB.

For an unchanged whole-CLI output/overhead control:

```sh
systemd-run --user --scope -q \
  -p MemoryMax=3700000000 -p MemorySwapMax=0 -- \
  python3 bench/stock-scaling/measure.py ../stock-2.0.39 \
  independent 32000 scratch-cli --cli
```

Compare `output_sha256` in the two receipt files. The published driver was tested this way on both stock versions on Boat; the campaign also matched both endpoints (2000 and 32000), three repetitions each. `patterns` generates the additional small string-case probe, where N is cases, not definitions.

To regenerate the wall-time fits from the sanitized raw records:

```sh
python3 bench/stock-scaling/fit.py bench/stock-scaling/results.json
```

A public exact reproducer of the private real-prefix measurements is intentionally unavailable. Their sizes, completed-phase metrics and failure outcomes are evidence of resource pressure, not a substitute for a public minimal superlinear-compiler reproducer.
